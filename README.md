# Scopewise: estimates that learn

**The problem.** A client sends a few emails, a meeting transcript and a Jira ticket, and someone has to say how long it will take. The answer is usually one number. It has no visible assumptions and no record of how wrong the last one was.

**Scopewise** turns that brief pack into an effort estimate you can defend:
- It splits the work into **phases and work items**, each citing the source line it came from.
- It lists **assumptions, missing information and likely scope additions**.
- It ranks client questions by **how much each answer would narrow the estimate**.
- It gives a **P50 to P80 range** per phase and in total, with **one visible buffer**, a **confidence level** and the **chance of meeting the deadline**.

Change the team shape and the timeline moves. Push the approved estimate to Jira as an epic with stories. When projects close, actual hours feed back in: a post-mortem explains each miss, lessons are saved, and the accuracy chart shows error falling.

**Live demo:** `https://<user>.github.io/agent-in-the-shell-estimator/`. It runs entirely in the browser with no backend; [SETUP.md](SETUP.md) explains how to publish it.

> **Everything is fictional.** Clients, people, squads, projects and hours are invented and generated by a seeded script.

## What to try (no install)

1. Open a sample on the home page. One click goes from the brief to a phased estimate with a buffer.
2. Press any **?** next to a number. A drawer shows the method, formula, inputs and citation. No number on screen comes from the language model.
3. Under **Answer a question**, mark the top question answered. The range tightens live, and the confidence level and buffer update.
4. On **Team & timeline**, add an engineer. The finish date moves earlier, but effort rises because of coordination overhead (Brooks). The integration sample also has a planned leave inside its window.
5. On **Learning**, the walk-forward backtest shows calibrated error against the raw panel. The P80 hit rate is ~78%. Press **Why** on a project to see the post-mortem.
6. Press `/` anywhere to Ask. Demo mode gives prepared answers; live mode uses Claude, which calls the engine as tools.

## Methods

| Step | Method | Citation |
|---|---|---|
| Outside view | Reference class: P20/median/P80 of actual hours for the same type and size | Kahneman & Tversky (1979); Flyvbjerg (2006) |
| Similar work | k = 3 nearest past items: same category, then complexity, then TF-IDF cosine | Shepperd & Schofield (1997) |
| Panel | Wideband Delphi, 3 personas × 2 rounds: o = min, m = median, p = max; flag if CV(m) > 0.35 | Boehm (1981) |
| Blend | m′ = w·median(analogs) + (1−w)·r_c·m_panel, w = n/(n+3) | Shepperd & Schofield (1997) |
| Bias | log r_c = n_c/(n_c+5) · mean log(actual/estimate), with coordination overhead divided out | Spolsky (2007); Efron & Morris (1975) |
| Items | Beta-PERT(o, m′, p) | Malcolm et al. (1959) |
| Simulation | 5,000 seeded runs (mulberry32): one shared project error factor, a shared factor per open question, Brooks overhead (+10% per extra person), absence, planned leave; phases in order, items in parallel across headcount | Metropolis & Ulam (1949); Brooks (1975) |
| Buffer | √Σ(P80ᵢ − P50ᵢ)² + open-question spread + absence × ΣP50; commit = ΣP50 + buffer | Goldratt (1997); Newbold (1998) |
| Confidence | High if P80/P50 < 1.25 and no high-impact questions are open; Low if P80/P50 > 1.6 or 3+ questions are open | — |
| Questions | Value of information: re-simulate with each question answered (common random numbers) and rank by the drop in P80 − P50 | Howard (1966) |
| Accuracy | MMRE, PRED(25), P80 hit rate; walk-forward backtest using only earlier projects | Conte, Dunsmore & Shen (1986) |

Two modelling choices go beyond the brief. Both are documented in the drawers and in `CLAUDE.md` under Decisions:
- **Items run late together.** Without a shared project-level factor, independent items average out and P80 sits only ~4% above P50. With it, the backtest's P80 hit rate is ~78%.
- **An open question is one unknown.** It moves all its items together, which makes value of information meaningful: answering the SMS question narrows the reminders estimate by ~17h.

Backtest on the seed history: raw panel MMRE **19%**, calibrated engine **15%**. PRED(25) rises from 68% to 83%.

## Run locally

```bash
npm install
npm run dev          # web, demo mode: http://localhost:5173
npm run dev:api      # API: http://localhost:8787 (copy apps/api/.env.example to apps/api/.env first)
VITE_API_BASE_URL=http://localhost:8787 npm run dev   # web in live mode
```

Checks (all run in CI):

```bash
npm run typecheck && npm run lint && npm test && npm run eval && npm run build
```

Data:

```bash
npm run seed                       # regenerate data/seed (fixed seed 1789)
npm run precompute                 # regenerate data/demo-cache offline
npm run precompute -- --live       # ...with real Claude (needs ANTHROPIC_API_KEY)
npm run push-to-jira -- --dry-run  # load the seed history into Jira Cloud (idempotent)
```

## Deploy

- **Web → GitHub Pages:** `.github/workflows/pages.yml` builds on every push to `main`. Set Pages → Source to GitHub Actions, and make the repo public.
- **API → Vercel:** set the root directory to `apps/api` and add the env vars from `apps/api/.env.example`. Then set the repo variable `VITE_API_BASE_URL` to the API URL.

Exact clicks are in [SETUP.md](SETUP.md).

## What's fake, and where AI outputs come from

- **Seed history:** generated by `scripts/seed.ts` with planted patterns:
  - integrations overrun ~1.4×, reporting comes in at ~0.9×;
  - form digitizations often add e-signature after kickoff;
  - ~8% absence, plus one planned leave;
  - the first 10 projects are noisier;
  - two time-entry typos.
- **Sample brief packs:** written for this project, with deliberate gaps (`data/samples/*/brief.json` lists them).
- **Demo cache:** no API key was available when this repo was built, so the committed cache is labelled honestly. The UI shows each output's provenance:
  - scope results are hand-written fixtures that follow the scope prompt's contract (`fixture-scope@1`);
  - panel guesses and post-mortem notes come from deterministic offline heuristics (`offline-heuristic-*`).
  
  Run `npm run precompute -- --live` with a key to replace them with Claude output. `npm run eval` checks either version.
